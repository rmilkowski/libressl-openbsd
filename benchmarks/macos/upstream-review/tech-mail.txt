Subject: libcrypto: four-block NEON ChaCha on little-endian arm64

This adds a private four-block ChaCha helper using baseline Advanced
SIMD on little-endian AArch64. Short inputs and tails keep scalar
processing. The twenty rounds, both key sizes, 64-bit counter/nonce,
carry and wrap, public context and streaming cache are preserved.

The target guard requires compiler-advertised AArch64, NEON and
little-endian byte order. Compiler targets without NEON, including
-mgeneral-regs-only, retain scalar code. This is intrinsic C;
OPENSSL_NO_ASM must not disable it because Portable sets that macro
automatically on macOS/AArch64 builds without an assembly backend.

The existing public regression gains bulk-boundary, alignment, counter,
in-place, split/cache, zero-length and continuation coverage against
single-byte calls, which cannot reach the helper. Cache-state
comparisons validate their lengths before pointer arithmetic.

Current Portable e255d87 passes all 149 tests in macOS arm64 distcheck,
CMake static and CMake shared builds, and in x86-64 CMake builds
executed under Rosetta. Linux x86-64 and arm64 pass the upstream recipe,
including arm64 Clang ASan CMake builds with assembly on/off. MSVC x64
and Win32, static/shared, each pass 145 tests.

OpenBSD 8.0 amd64 and arm64 VMs compile and run the actual translation
unit and regression with Clang 22.1.6. The arm64 job checks NEON
selection and -mgeneral-regs-only scalar fallback. This is not a full
OpenBSD -current or base-system integration build.

Separate original-scalar comparisons pass 7,200 protected-page cases,
165,888 independent-alignment cases and 49,488 broader differential
cases, with fatal ASan/UBSan checks. Supplemental KNF formatting,
warnings-as-errors and Clang analyzer checks pass.

Measurements of revision 289dcecb on M1 Max reduced combined SSH
endpoint CPU by 21.1% and elapsed time by 20.5% for uncompressed 512 MiB
SFTP transfers; 32 KiB primitive CPU fell 54.5%. The subsequent source
style and test cleanup in this diff produces identical optimized Mach-O
text under that compiler, but has not been freshly benchmarked. No
OpenBSD performance gain or general compression-enabled speedup is
claimed.

The different OpenBSD unaligned-access code generation and larger stack
frame remain review topics. OpenBSD -current/full-library integration
and representative native-hardware performance need more validation.

This was developed with Codex assistance and reviewed with an Astra
model. That is assistance disclosure, not an OpenBSD maintainer review
or independent human cryptographic audit.

+/*
+ * Process four complete blocks. Each vector holds one state word from each
+ * block; words 12 and 13 carry the low and high halves of the 64-bit counter.
+ * Counter additions wrap modulo 2^64, as in the scalar implementation.
+ * The byte permutations and output stores require a little-endian target.
+ */
+static void
+chacha_encrypt_four(chacha_ctx *ctx, const u8 *in, u8 *out)
+{
+	const uint8x16_t rotate8 = {
+		3, 0, 1, 2, 7, 4, 5, 6, 11, 8, 9, 10, 15, 12, 13, 14
+	};
+	uint32x4_t x[16];
+	uint32x4_t a, b, base, c, d;
+	uint8x16_t rows[4];
+	uint64_t counter, n;
+	uint32_t high[4], low[4];
+	unsigned int i, k, r;
+
+	counter = ((uint64_t)ctx->input[13] << 32) | ctx->input[12];
+	for (k = 0; k < 4; k++) {
+		n = counter + k;
+		low[k] = (uint32_t)n;
+		high[k] = (uint32_t)(n >> 32);
+	}
+	for (i = 0; i < 16; i++)
+		x[i] = vdupq_n_u32(ctx->input[i]);
+	x[12] = vld1q_u32(low);
+	x[13] = vld1q_u32(high);
+
+	for (r = 0; r < 10; r++) {
+		CHACHA_NEON_QUARTERROUND(x[0], x[4], x[8], x[12]);
+		CHACHA_NEON_QUARTERROUND(x[1], x[5], x[9], x[13]);
+		CHACHA_NEON_QUARTERROUND(x[2], x[6], x[10], x[14]);
+		CHACHA_NEON_QUARTERROUND(x[3], x[7], x[11], x[15]);
+		CHACHA_NEON_QUARTERROUND(x[0], x[5], x[10], x[15]);
+		CHACHA_NEON_QUARTERROUND(x[1], x[6], x[11], x[12]);
+		CHACHA_NEON_QUARTERROUND(x[2], x[7], x[8], x[13]);
+		CHACHA_NEON_QUARTERROUND(x[3], x[4], x[9], x[14]);
+	}
+	for (i = 0; i < 16; i++) {
+		if (i == 12)
+			base = vld1q_u32(low);
+		else if (i == 13)
+			base = vld1q_u32(high);
+		else
+			base = vdupq_n_u32(ctx->input[i]);
+		x[i] = vaddq_u32(x[i], base);
+	}
+
+	/* Transpose four words at a time back into consecutive blocks. */
+	for (i = 0; i < 16; i += 4) {
+		a = vtrn1q_u32(x[i], x[i + 1]);
+		b = vtrn2q_u32(x[i], x[i + 1]);
+		c = vtrn1q_u32(x[i + 2], x[i + 3]);
+		d = vtrn2q_u32(x[i + 2], x[i + 3]);
+		rows[0] = vreinterpretq_u8_u32(vcombine_u32(vget_low_u32(a),
+		    vget_low_u32(c)));
+		rows[1] = vreinterpretq_u8_u32(vcombine_u32(vget_low_u32(b),
+		    vget_low_u32(d)));
+		rows[2] = vreinterpretq_u8_u32(vcombine_u32(vget_high_u32(a),
+		    vget_high_u32(c)));
+		rows[3] = vreinterpretq_u8_u32(vcombine_u32(vget_high_u32(b),
+		    vget_high_u32(d)));

+			vst1q_u8(out + k * 64 + i * 4,
+			    veorq_u8(vld1q_u8(in + k * 64 + i * 4), rows[k]));
+		}
+	}
+	counter += 4;
+	ctx->input[12] = (uint32_t)counter;
+	ctx->input[13] = (uint32_t)(counter >> 32);
+}
